05a - Nonlinear Reduction and Embeddings
How can we turn 64 pixel measurements into a useful two-dimensional map?

A map places each observation in the two output coordinates of a dimensionality-reduction method.

PCA uses a linear combination of features to produce shared linear directions. Today we’ll explore representations built around which observations belong near one another.

2.0 Can Two Coordinates Describe a Bent Sheet?
Even with useful input coordinates, a linear projection like PCA can lose relationships we want to keep. Linear combinations are not always an adequate representation of the data.

A manifold is a space that can be described locally using ordinary coordinates of a fixed dimension. Consider a smooth sheet, with two independent directions of movement along it. Bending it through three-dimensional space does not add a third direction along the sheet. A small patch of our sheet is approximately flat, even though the whole sheet bends.

For this lecture we'll keep the following concepts separate:

Dimension	What It Describes	Our Example
Ambient	Surrounding measurement space	Three spatial coordinates
Intrinsic	Independent local coordinates on the manifold	Two directions along the sheet
Output	Coordinates requested from the method	Two PCA scores
To explore the idea we've constructed a synthetic dataset from two coordinates per observation: position along the bend and position across the sheet. These known intrinsic coordinates appear in the bottom strip.

We then used them to construct an S-shaped surface in three-dimensional space, then added a little noise. These three ambient coordinates are the synthetic measurements PCA receives. PCA produces two output coordinates, its component scores.

Follow the circle and square through the ambient, intrinsic, and output views. Which distinction does PCA lose?

2.1 Local Relationships
PCA finds directions in the ambient feature space that retain the most variance. Every observation gets output coordinates by linear projection onto those same directions. This approach ignores neighborhood relationships that may be important to consider.

A straight line through space can cut across a bend. A path along the sheet must follow the surface. Short steps between neighbors can help describe that surface, provided the measured neighbors trace it well. Noise, sparse samples, or nearby folds can create misleading connections.

None: rotating or translating all the intrinsic-coordinate points together preserves Euclidean distances and neighbor identities. Their coordinate values change, but those relationships stay the same.

def nearest_rows(values, k=10):
    distances = pairwise_distances(values, metric="euclidean")
    np.fill_diagonal(distances, np.inf)
    return np.argsort(distances, axis=1, kind="stable")[:, :k]

3.0 t-SNE: Match Similarities
t-SNE means t-distributed stochastic neighbor embedding.

An embedding represents observations by coordinates.

It keeps the ambient pixel coordinates fixed and searches for output coordinates that represent their similarities.

3.1 Turn Distances into Relationship Strengths
Start with four observations: A = 0, B = 1, C = 3, D = 4.5.

An affinity is a numerical relationship strength. Give a neighbor at distance  Gaussian weight 
, then divide by the sum of weights around the reference observation to get the probability.

From A, B receives weight . C receives .

Before running: Which observation should receive most of A’s probability?

toy_names = np.array(["A", "B", "C", "D"])
toy_x = np.array([[0.0], [1.0], [3.0], [4.5]])
toy_distances = pairwise_distances(toy_x)
toy_weights = np.exp(-(toy_distances**2) / 2)
np.fill_diagonal(toy_weights, 0)
toy_conditional = toy_weights / toy_weights.sum(axis=1, keepdims=True)
display(

3.2 t-SNE Algorithm
tl;dr

Define neighbor relationships in the original data, then repeatedly move points in the output map to approximate those relationships. Perplexity controls how broad a neighborhood influences that arrangement.

1. Decide how strongly each observation should regard the others as neighbors

For each observation:
Calculate its distances to other observations
Give nearby observations larger weights using Gaussian curve
Normalize those weights to sum to one
Interpret the result as a probability:
If A selected a neighbor using these weights, how likely would it be to select B?
Note: A and B have different neighbors, to the probabilities A→B and B→A are not symmetric.

2. Decide how many neighbors to consider with perplexity

If A assigned equal probability to exactly 30 neighbors and zero to all others, its perplexity is 30.
For unequal probabilities, perplexity expresses the equivalent number of equally likely neighhbors.
Increasing perplexity makes the output arrangement account for a broader neighborhood around each observation in the original data.
Perplexity is used to adjust the Gaussian width separately for each observation.
3. Combine the pair probabilities in the ambient dimension

For each pair of distinct observations (e.g. A, B):
Combine the two directional neighbor probabilities, A→B and B→A
Into one symmetric pair probability, 
These probs describe the relationship the output map will try to preserve
Result is a full set of pair probabilities, 
4. Give each observation an initial position in the output map

PCA is commonly used for this.
Gives an initial estimate of the output map.
Calculate a set of pair probabilities, 
, for the proposed map.
Use a heavier-tailed Student-t curve to calculate weights from output distances, then normalize them into pair probabilities.
Better accommodates the relationships in fewer dimensions where observations are inherently more crowded.

Use an iterative process to minimize the differences:

Do the same for B, C, D... all other observations.
Update the coordinates for all observations.
Recalculate  for the newly proposed map.

Small changes in the proposed map.
Reach the iteration limit.

4.0 UMAP: Build a Graph, Then Lay It Out

There are many ways to do dimensionality reduction. As our last example, we’ll briefly cover UMAP.

PCA finds directions that retain variance. t-SNE tries to preserve neighbor relationships expressed as probabilities. UMAP builds a network connecting each observation to its nearest neighbors, with stronger connections for observations that are closer relative to their local neighborhood.

UMAP means Uniform Manifold Approximation and Projection. A graph represents observations as nodes and their connections as edges. An edge weight says how strongly two observations connect.

Think of each observation as a dot and each connection as a link. UMAP then arranges the dots in a lower-dimensional output map, trying to keep strongly connected observations close together while balancing that attraction with separation between unconnected observations.

The process has three main steps:

Find neighbors in the original data. For each observation, identify nearby observations using the chosen distance measure.

Build the network. Assign connection strengths using distances relative to the local neighborhood, then combine the connections into one network.

Arrange the output map. Start with an initial layout and repeatedly adjust the output coordinates to better represent the network.

Two settings are especially useful to understand:

n_neighbors controls how many neighbors contribute to building the network. Smaller values emphasize more local relationships; larger values bring broader relationships into its construction.
min_dist controls how tightly points can pack in the output map. Smaller values allow tighter groups; larger values encourage more spread. It is not a strict minimum distance between every pair.
The resemblance between t-SNE and UMAP is substantial. Both define local relationships in the input, then move output points to represent them. For this course, the useful differences are:

A network representation: UMAP makes the neighborhood graph explicit. That provides a useful connection to later discussions of clustering and connectivity.
Separate controls for neighborhood and layout: n_neighbors changes the network being represented; min_dist changes how tightly its output points can pack. different layouts.
Placement of new observations: some UMAP implementations can transform new observations into an existing map.
We’ll fit UMAP to the same digit images, inspect the map, and check which original neighbors remain close.

5.3 Do Similar Images Share Digit Labels?
The maps appear to group images of the same digit. We can test a specific part of that observation:

In the original 64-pixel representation, do neighboring images share digit labels more often than we would expect if labels were unrelated to the pixel patterns?

This checks whether the relationship exists before dimensionality reduction.

For each image, calculate the fraction of its ten nearest neighbors that share its digit label. Average those fractions across all 600 images. Larger values indicate stronger agreement between pixel-based neighborhoods and digit identity.

def neighbor_label_agreement(labels, neighbors):
    matches = labels[neighbors] == labels[:, None]
    return matches.mean()


observed = neighbor_label_agreement(digit_labels, input_neighbors)

Null hypothesis: digit labels are exchangeable among the images; their assignment is unrelated to the fixed pixel-based neighborhoods.

Under this null model, we can shuffle the labels while keeping the images and neighbor lists unchanged. Each shuffle preserves the number of zeros, ones, and other digits, but breaks their association with the pixel patterns.

07a - Fitting K-Means and Choosing Groups
Last time, K-means divided 72 simulated customers using two measurements: requests last term and average minutes per request. We compared two- and three-group results. Today we will look more closely at how K-means fits those groups and what evidence might help us choose among them.

The simulation has no built-in customer types. A useful question is whether a proposed grouping would help a service team investigate or plan support. A fitted partition alone cannot answer that question.

References
Scikit-learn K-means guide: the squared-distance objective, algorithm, initialization, and limits.
Scikit-learn KMeans reference: fitting options and the values stored after a fit.
Scikit-learn silhouette guide: a measure of within-group closeness and between-group separation.
How K-Means Forms Groups
K-means starts with a requested number of groups, . It assigns each point to the nearest current center, then moves each center to the mean of its assigned points. It repeats those steps until the centers settle or an iteration limit is reached. Different starting centers can produce different results, so a fit may try several starts.

For each start:
    Choose K initial centers.
    Repeat:
        Assign every point to its nearest center.
        Replace each center with the mean of its assigned points.
    Stop when the centers move little enough or an iteration limit is reached.
    Compute the inertia of that start.
Keep the completed run with the lowest final inertia.
Next we will define inertia, then calculate it in a four-point example.

Inertia, the Total Squared Distance
K-means tries to put each observation near the center of its assigned group. For each observation, square its distance to that center, then add the squared distances over all observations. Scikit-learn calls this total inertia. A smaller value means a tighter fit in the chosen feature space.

If  is observation  in the feature space given to K-means, and  is the center of its assigned group, the total is

 

Assignment chooses the smallest squared distance for each point when the centers are fixed. The mean minimizes the squared-distance total for a group's points when its assignments are fixed. Each step reduces or preserves inertia under that condition.

The next example has four points on a number line. We ask for two groups and start with centers at 1 and 2. Inspect the points before following the fit.

From the Algorithm to Scikit-Learn
Scikit-learn uses a recurring sequence:

Instantiate: Create an object and set its options, such as StandardScaler() or KMeans(n_clusters=2).
Fit: Give the object data. StandardScaler.fit() learns column means and standard deviations; KMeans.fit() learns centers and assignments.
Inspect: Read fitted results from attributes ending in _ by convention, such as mean_, cluster_centers_, labels_, and inertia_. Constructor settings such as n_clusters have no trailing underscore.
Apply: Use the fitted scaler's transform() to scale rows, then the fitted K-means model's predict() to assign a group. fit_transform() combines fitting and transforming the initial data. KMeans.transform() instead returns distances to centers.
We will use separate fit and transform calls below so each step is visible.

Starting and Stopping a Fit
Each K-means run needs starting centers. The default init="k-means++" favors observations far from centers already chosen, which generally gives the fit a better start than selecting observations uniformly at random. It changes how a run starts, not the assignment-and-update steps that follow. In our four-point example, if 1 were chosen first, k-means++ would favor a distant point such as 8 or 9 next. init="random" instead samples observed rows without that distance preference. We can also supply initial centers or a function that chooses them.

The n_init setting says how many complete runs to try from different starts; K-means keeps the run with the lowest final inertia. In the course's scikit-learn version, n_init="auto" means one run with k-means++, ten with random or a function, and one with supplied centers. We set n_init=20 to reduce dependence on a single start in this example and to compare one start with the best of 20 below. Twenty is a teaching choice, not a required value.

These are constructor settings: we choose them when creating KMeans(...), and fit(scaled_customers) uses them with the supplied data. The last column shows defaults in the course's scikit-learn version. max_iter and tol control stopping within each run; we leave them at their defaults.

2. Build Up Through Merges
Hierarchical clustering generally uses either a top-down or bottom-up approach, using recursive splitting or joining, respectively. Formally, these are called divisive or agglomerative methods.

We will focus on the agglomerative clustering approach. It starts with one cluster per observation and builds larger clusters through merges. At each step, it joins the closest pair of current clusters until all observations are combined in a single cluster.

Choose the feature representation, point distance, and linkage rule.
Start with one cluster per observation.
Repeat until only one cluster remains:
    Find the closest pair of current clusters.
    Join them and record the results, including the new cluster size.
    Update distances from the new cluster to the remaining clusters.
Return the merge history.
The feature coordinates and original point distances stay fixed. Cluster membership changes, so distances between current clusters must be updated. Each merge reduces the cluster count by one. Once joined, a cluster stays together in later merges.

This algorithm is greedy: it joins the closest available clusters under the chosen cluster-distance rule and never revisits that decision. Early merges cannot be undone, so later clusters depend on those local choices. A cut is not guaranteed to give the globally best partition for its cluster count.

SciPy is a scientific-computing library built on NumPy. It provides algorithms for tasks such as optimization, statistics, and clustering. This notebook uses its scipy.cluster.hierarchy module to build, draw, and cut a hierarchy.

The value 3.16 comes from A to C. The point distances have not changed; we have chosen how to turn them into one cluster distance.

This cluster distance is the merge height: the value at which the two clusters join, shown vertically in the dendrogram. Here, {A,B} joins C at a height of about 3.16.

Other linkage rules answer different questions about cluster closeness:

Single linkage uses the nearest cross-pair. It can reveal connected or elongated patterns, although a few short connections can create long chains.
Average linkage uses the mean of all cross-pair distances. It suits a comparison based on overall closeness rather than one nearest or farthest pair.
Ward linkage chooses the merge with the smallest increase in within-cluster squared distance. It is useful when compact clusters are the goal and Euclidean geometry is appropriate.

5.3 Other Ways to Extract Clusters
The criterion argument controls how fcluster() extracts clusters from the same tree. It also changes what t means. The SciPy reference lists five options:

Criterion	How it chooses clusters
distance	Cut at the merge-height threshold t, as above.
maxclust	Find the smallest height threshold that produces at most t clusters.
inconsistent (default)	Apply threshold t to a measure of how unusual a merge height is relative to nearby merges below it.
monocrit	Apply threshold t to a supplied statistic that never decreases as we move up the tree.
maxclust_monocrit	Choose a threshold on that supplied statistic to produce at most t clusters.
Use distance when a height threshold matters and maxclust when a cluster-count limit matters. The other options require a local inconsistency measure or a custom statistic; we will leave their details for further study.

This brings us back to K-means: we can ask for a cluster count instead of choosing a distance threshold. K-means fits centroids for a chosen . Here, maxclust extracts at most  clusters from an already-built hierarchy; changing the requested count changes the cut, without refitting the tree. The resulting partitions remain nested, whereas separate K-means fits at different values of  need not be nested.

Unlike K-means, agglomerative clustering has no random starting centers. With fixed data and row order, representation, distance, linkage, and implementation, this workflow reproduces the same hierarchy. Tied distances can admit different merge orders, so tie handling also matters.

6. Other Definitions of Close Clusters
For {A,B} and {C}, the cross-pair distances remain  and . Single linkage uses their minimum, about 2.24. Average linkage uses their mean, about 2.70. Complete linkage uses their maximum, about 3.16. Changing linkage changes the meaning of a candidate join, even with the same observations and point distances.

Linkage	Criterion for joining two clusters
Single	Smallest distance between a member of each cluster.
Complete	Largest distance between a member of each cluster.
Average	Mean of all cross-pair distances.
Ward	Smallest increase in total within-cluster squared distance after a merge.
Ward linkage connects to the squared-distance objective from K-means. It chooses the available merge that adds the least within-cluster squared distance, using Euclidean geometry. K-means can reassign points while updating centers for a fixed K; Ward joins existing clusters irreversibly. Their partitions need not agree.

For single linkage, one short connection can join two clusters even when their other members are far apart. This can create chains. Compare the same six observations at two clusters under single and complete linkage.

    tree = linkage(toy, method=method, metric="euclidean")

8. Use a Hierarchy With a Purpose
This workflow builds a hierarchy, extracts a cut, and inspects its existing members. It does not provide K-means' nearest-center prediction for a later customer. def plot_groups(ax, x, labels, title):
    for label in np.unique(labels):
        selected = labels == label
        ax.scatter(
            *x[selected].T, s=22, alpha=0.8,
            color="0.25" if label == -1 else COLORS[int(label) % len(COLORS)],

def add_component_contours(ax, model):
    for component, (mean, covariance) in enumerate(
        zip(model.means_, model.covariances_, strict=True)
    ):
        eigenvalues, eigenvectors = np.linalg.eigh(covariance)
        angle = np.degrees(np.arctan2(eigenvectors[1, 1], eigenvectors[0, 1]))

            mean, 4 * np.sqrt(eigenvalues[1]), 4 * np.sqrt(eigenvalues[0]),

        ))

Density-Based Clustering
Suppose observations trace two curved regions. Assigning every point to its nearest center can cut across those regions. Another definition of a cluster is a region we can travel through by moving between sufficiently dense neighborhoods.

DBSCAN stands for Density-Based Spatial Clustering of Applications with Noise. It forms groups using this neighborhood idea and can leave some observations unassigned. We choose the local density rule; the resulting number of clusters is an output.

Neighborhoods, Core Points, and Border Points

eps (epsilon, ) is the radius within which observations count as neighbors, including points exactly at the radius.

A border point is not core but lies within the radius of a core point. A noise point is neither core nor a neighbor of any core point. These roles describe the current data under the selected settings.

A, B, C, and D have enough neighbors to be core. E's neighborhood contains exactly D, E, and F. D and F lie on its boundary and both count. E has only three neighbors, including itself, but is close to core point D, so E is border. F is close to E but not to any core point. F and G are noise.

DBSCAN builds a cluster by following connections among core points, then including adjacent border points. A border point can join a cluster but cannot extend it to its own neighbors. This is how a chain of core neighborhoods can follow a curved region. Points at opposite ends can be much farther apart than eps.

Pause: A Border Is Not a Bridge
E belongs to the cluster containing D. F is close to E, so why does F remain noise? With a radius of 0.5 and min_samples=4, check whether each point is near a core point, rather than just any cluster member.

Answer
D is a core point because its neighborhood contains five points, meeting the minimum count of four. E lies within D's radius, so E joins the cluster containing D.

E's own neighborhood contains only D, E, and F: three points, including E itself. E is therefore a border point, not a core point.

F lies within E's radius, but outside the radius of every core point. Being close to border point E is not enough, so F remains noise. A non-core point joins a cluster only if it is within the radius of a core point.

If we lowered min_samples to three while keeping the same radius, E would become core. F would then join the cluster as a border point because it is within E's radius.

Gaussian Mixture Models
Density connectivity is one way to define a group. Another possibility is that observations come from several overlapping distributions. Their locations and spreads may differ, and an observation in an overlap may be compatible with more than one component.

A Gaussian mixture model, or GMM, describes the data with a weighted combination of Gaussian distributions. A Gaussian is the familiar normal distribution: its mean locates the center and its variance describes spread. With two features, a Gaussian describes a cloud whose spread can differ by direction.


cloud_rng = np.random.default_rng(7130)
clouds = np.vstack([
    cloud_rng.multivariate_normal([-1.4, 0], [[1.2, 1.0], [1.0, 1.2]], 240),
    cloud_rng.multivariate_normal([1.4, 0], [[0.7, 0.5], [0.5, 0.8]], 160),
])
fig, ax = plt.subplots(figsize=(7, 4.5), layout="constrained")
ax.scatter(*clouds.T, color="0.35", s=20, alpha=0.75)
ax.set(title="400 Observations From Two Overlapping Distributions",
       xlabel="Coordinate 1", ylabel="Coordinate 2")
ax.set_aspect("equal")
plt.show()
     
We generated 240 observations from one tilted distribution and 160 from another. The fitting methods receive only their coordinates. Can they recover the overlapping structure without being told which distribution generated each point?

Centers, Spreads, and Component Weights
Each Gaussian component has three kinds of fitted quantities:

Quantity	Meaning
Mean	The center in the feature space
Covariance	Variation along each feature and how features vary together
Weight	The component's share of the fitted mixture; the weights sum to one
In two dimensions, covariance controls the width and tilt of elliptical contours. A tilted cloud means that deviations in the two features tend to move together. Allowing a separate covariance for each component gives the model more flexibility than comparing distance to centers alone.

How the Mixture Is Fitted
The component distributions are unknown, and so are the observations' memberships. Fitting alternates between estimates of the two:

Start with provisional component means, covariances, and weights.
Use those components to estimate relative membership probabilities for every observation.
Update the components using all observations, weighted by those membership probabilities.
Repeat until the improvement in likelihood is small enough or an iteration limit is reached.
This is expectation-maximization, or EM. Likelihood measures how well the fitted distributions account for the observed data. Membership estimates guide the next component estimates, which then give us revised memberships. The data and requested component count stay fixed. Different starts can lead to different fits, so we try several.

Fit and Inspect the Components
Start with two components. covariance_type="full" lets each have its own spread and orientation. As with K-means, n_init=10 means ten complete fits from different starts. Here the model retains the fit with the highest likelihood. random_state makes the starts reproducible.

After fitting, check converged_. The model stores the learned means, covariances, and weights. predict(X) returns the most probable component for each row, while predict_proba(X) retains all the membership probabilities.

Choosing the Covariance Type
We used covariance_type="full" so each component could follow its own tilted cloud. The alternatives restrict which shapes the model can fit.

covariance_type	Component Shapes in Two Dimensions	When It May Be Useful
"full"	Each component has its own size, elongation, and tilt.	Groups have different spreads and correlations, with enough observations to estimate them.
"tied"	All components share the same size, elongation, and tilt; their centers differ.	Groups have similar internal variation. Sharing covariance reduces the amount to estimate.
"diag"	Each component has its own horizontal and vertical spread, with no tilt.	Within-component feature correlations are negligible, or estimating all correlations requires too much data.
"spherical"	Each component is circular, with its own radius.	Roughly round groups are plausible. Feature scaling matters because spread is equal in every direction within a component.
These restrictions trade flexibility for fewer parameters. With ten features, a full covariance needs 55 values per component, diagonal needs ten, and spherical needs one. Tied estimates one shared set of 55 covariance values.

Spherical GMM is closest in spirit to K-means: both favor round groups, but GMM supplies membership probabilities. Its components can also have different spreads and weights, so their assignments need not match K-means. The probabilities come from fitting the mixture model, rather than being added to a K-means partition.

Compare the same observations with two components in every panel. Only the covariance type changes; all fits use ten starts and the same random seed. Which shapes can follow the tilt, and which assignments change when that flexibility is removed?

Elbow, Silhouette, and Gap
The elbow looks for diminishing reductions in inertia, the same sum of squared distances from observations to their assigned centers used earlier. Silhouette asks whether points are closer to their own cluster than to the nearest competing cluster. It is undefined for one cluster because there is no competitor.

A higher silhouette score indicates better separation by this measure. When several counts give nearly the same score, parsimony favors a simpler grouping unless the extra clusters add a useful distinction. This is an analytical judgment alongside the score, not a formal silhouette rule. Silhouette also favors compact, separated groups and can undervalue a useful curved grouping.

Adding more centers reduces inertia even in random data. The gap statistic asks whether another cluster is doing meaningful work: does it improve the fit beyond what we would expect from partitioning random reference data?

We return to the same 72 simulated customers used in 07a, standardizing requests and average minutes per request as before. For comparison, we generate 100 reference datasets of 72 points each, spread uniformly across a region with a similar range and orientation. This is our no-group reference: it has no deliberately planted groups, although random clumps can occur. It covers a similar region without reproducing the customer data's exact variance or density.

We fit K-means to the customers and each reference dataset with one through eight clusters. Gap compares their inertias on a logarithmic scale. A larger gap means the customer clustering is more compact relative to these no-group reference fits.

Starting with one cluster, ask whether adding another increases that advantage by more than the variation in the simulations. If it does, continue. If the increase is small enough to fall within the simulation allowance, or gap decreases, stop and keep the smaller count. The bars show that allowance. Choose the simpler grouping once another cluster no longer gives a clear improvement relative to the random reference.

Here, “meaningful work” means describing structure relative to this uniform reference. Whether another group would help the service team make a decision still needs separate evidence.


def compare_cluster_counts(x, max_k=8, n_reference=100, seed=810):
    """Compare K-means counts with a PCA-aligned uniform gap reference.

    Implementation detail: center and rotate into principal-component directions,
    keeping both dimensions and their scales. Draw uniformly within those ranges.
    Rotation preserves observed distances but determines the reference box.

    Gap(k) = mean_b(log W_reference[b, k]) - log W_observed[k].
    Average the logs, not the inertias before taking a log.
    s(k) = SD_b(log W_reference[b, k]) * sqrt(1 + 1/B).
    Choose the first k with Gap(k) >= Gap(k+1) - s(k+1).
    Bars display s(k), not confidence intervals for a true count. The last
    candidate supplies the next-count comparison; extend the range if none passes.

    """
    counts = np.arange(1, max_k + 1)
    fits = [KMeans(n_clusters=int(k), n_init=20, random_state=7130).fit(x)
            for k in counts]
    inertia = np.array([fit.inertia_ for fit in fits])
    silhouette = [np.nan] + [silhouette_score(x, fit.labels_) for fit in fits[1:]]

    centered = x - x.mean(axis=0)
    _, _, directions = np.linalg.svd(centered, full_matrices=False)
    rotated = centered @ directions.T
    rng = np.random.default_rng(seed)
    reference_log_w = np.empty((n_reference, max_k))
    for b in range(n_reference):
        reference = rng.uniform(rotated.min(axis=0), rotated.max(axis=0), size=x.shape)
        for j, k in enumerate(counts):
            fit = KMeans(n_clusters=int(k), n_init=20, random_state=7130).fit(reference)
            reference_log_w[b, j] = np.log(fit.inertia_)

    gap = reference_log_w.mean(axis=0) - np.log(inertia)
    allowance = reference_log_w.std(axis=0, ddof=1) * np.sqrt(1 + 1 / n_reference)
    qualifies = gap[:-1] >= gap[1:] - allowance[1:]
    selected = int(counts[:-1][qualifies][0]) if qualifies.any() else None
    table = pd.DataFrame({
        "k": counts, "Inertia": inertia, "Silhouette": silhouette,
        "Mean reference log W": reference_log_w.mean(axis=0),
        "Gap": gap, "Simulation allowance": allowance,
    }).set_index("k")
    return table, selected

Stability Under Changed Observations
Would we find similar groups if our sample had included a somewhat different set of observations? To explore that question, treat the observed dataset as a stand-in for the population. Repeatedly draw a random 80% of its rows without replacement, fit the two-component GMM again, and compare the assignments for observations included in both fits. The 80% fraction is a demonstration choice.

Changing random starts on the full dataset checks sensitivity to initialization. Refitting subsets explores sensitivity to which observations are included. Each refit here uses ten starts to reduce the influence of initialization while keeping the component count and covariance form fixed.

These subsamples overlap and reuse observations we already have. They show how the grouping responds to changes within this dataset; they do not reproduce collecting independent new samples from the actual population.

Compare each new partition with the original fit on the sampled rows. The adjusted Rand index, or ARI, checks whether pairs of observations stay together or apart, allowing for chance agreement. It ignores label numbers. One means identical partitions; zero means chance-level agreement, and negative values mean less agreement than expected by chance.

Why an Ordinary Test Can Mislead
Suppose we use K-means to form groups, then run a t-test comparing their means on one of the clustering features. We have used the same measurements twice: first to choose groups that differ, then to test that difference as though the groups had been specified independently.

This is double dipping, a problem for post-selection inference: the ordinary t-test does not account for how the groups were selected. It resembles leakage because information used to construct the result is reused to evaluate it. A small p-value can partly reflect that construction, even when the observations came from one population.

The t-test tests a difference in means; it does not test whether clusters are real populations. Statistical significance is not guaranteed after clustering, either. To see the problem in this example, generate 400 observations from one Gaussian population, ask K-means for two clusters, and apply an ordinary t-test to coordinate 1.


single_cloud = np.random.default_rng(108).multivariate_normal(
    mean=[0, 0], cov=[[1, 0.4], [0.4, 1]], size=400,
)
single_fit = KMeans(n_clusters=2, n_init=20, random_state=7130).fit(single_cloud)
single_labels = single_fit.labels_
naive_result = ttest_ind(
    single_cloud[single_labels == 0, 0],
    single_cloud[single_labels == 1, 0],
    equal_var=False,
)
print(f"Ordinary post-clustering t-test p-value: {naive_result.pvalue:.2e}")
print("This p-value is invalid as evidence of separate populations after this selection.")
     

fig, axes = plt.subplots(1, 2, figsize=(10.5, 4.2), sharex=True, sharey=True,
                         layout="constrained")
axes[0].scatter(*single_cloud.T, color="0.4", s=20, alpha=0.7)
axes[0].set(title="Generated From One Gaussian Population", xlabel="Coordinate 1",
            ylabel="Coordinate 2")
axes[0].set_aspect("equal", adjustable="box")
plot_groups(axes[1], single_cloud, single_labels, "The Same Observations Split by K-Means")
plt.show()
     
The p-value is extremely small even though the observations came from one Gaussian population. K-means supplied the split using the same coordinates we tested. The ordinary p-value calculation ignores that selection, so its usual interpretation is unreliable here.

A difference we deliberately created is not independent evidence that distinct populations exist.

Unlike typical train/test leakage, a simple holdout does not necessarily fix this. Assigning new observations to clusters using these same features can also create differences by construction. Shuffling the final labels would likewise omit how we found the groups. The next comparison includes the clustering procedure itself: fit clusters to each simulated reference dataset before measuring separation.

A Single-Population Reference
We ask whether one continuous Gaussian cloud could produce a split as strong as the one we found. We fit a single Gaussian to the data, generate many new datasets from it, and ask K-means to split each into two groups. We then compare how much those splits reduce squared distances with the reduction in our original data. If our split is unusually strong, that is evidence that the single-Gaussian description may be inadequate, but it does not prove there are exactly two real or useful groups.

The reference cloud can be elongated or tilted. Choosing a Gaussian is an assumption about what one population might look like.

Return to the two cloud examples: the single Gaussian used in the t-test demonstration and the overlapping clouds used for GMM. For each, compare K-means inertia with two centers to inertia with one center. Divide the two-center value by the one-center value. A ratio of 0.5 means that two centers leave half the original sum of squared distances. Smaller ratios mean a larger improvement from splitting the data.


def two_center_ratio(x):
    two_centers = KMeans(n_clusters=2, n_init=20, random_state=7130).fit(x)
    total_dispersion = np.sum((x - x.mean(axis=0)) ** 2)
    return two_centers.inertia_ / total_dispersion


print(f"One-cloud ratio: {two_center_ratio(single_cloud):.3f}")
print(f"Overlapping-cloud ratio: {two_center_ratio(clouds):.3f}")
     
The ratios are about 0.535 for the single cloud and 0.424 for the overlapping clouds. The second split removes more of the original squared distance. For each dataset separately, we fit its own single-Gaussian reference and generate 499 datasets of the same size for comparison.

This is a parametric bootstrap: we generate new observations from a fitted model, whereas the ARI check sampled existing rows. Refitting K-means in every simulation includes the grouping step that the ordinary t-test ignored.

In each histogram below, the bars count simulated datasets, and the vertical line marks the observed ratio. A line far to the left means the observed split improved the fit more than most simulated splits.


def gaussian_reference_comparison(x, repetitions=499, seed=806):
    fitted_mean = x.mean(axis=0)
    fitted_covariance = np.cov(x, rowvar=False, ddof=0)
    observed_ratio = two_center_ratio(x)
    reference_rng = np.random.default_rng(seed)
    reference_ratios = np.empty(repetitions)
    for repeat in range(repetitions):
        reference_sample = reference_rng.multivariate_normal(
            fitted_mean, fitted_covariance, size=len(x),
        )
        reference_ratios[repeat] = two_center_ratio(reference_sample)
    # Smaller ratios indicate greater separation by this statistic.
    at_least_as_separated = np.count_nonzero(reference_ratios <= observed_ratio)
    tail_estimate = (at_least_as_separated + 1) / (repetitions + 1)
    return observed_ratio, reference_ratios, at_least_as_separated, tail_estimate


reference_results = {
    "One Gaussian cloud": gaussian_reference_comparison(single_cloud),
    "Overlapping clouds": gaussian_reference_comparison(clouds),
}
reference_summary = pd.DataFrame([
    {"Data": name, "Observed ratio": result[0],
     "Reference samples at least as separated": result[2],
     "Approximate lower-tail estimate": result[3]}
    for name, result in reference_results.items()
]).set_index("Data")
display(reference_summary.round(3))
     

fig, axes = plt.subplots(1, 2, figsize=(11, 4), sharex=True, sharey=True,
                         layout="constrained")
all_ratios = np.concatenate([np.r_[r[0], r[1]] for r in reference_results.values()])
bins = np.linspace(all_ratios.min() - 0.01, all_ratios.max() + 0.01, 26)
for ax, (name, result) in zip(axes, reference_results.items(), strict=True):
    observed, simulated, count, tail = result
    ax.hist(simulated, bins=bins, color=COLORS[0], alpha=0.75,
            label="499 refitted Gaussian reference samples")
    ax.axvline(observed, color=COLORS[1], linewidth=2.5, label="Observed ratio")
    ax.set(title=name, xlabel="Two-center / one-center dispersion ratio",
           ylabel="Reference samples")
    ax.legend(fontsize=8, loc="upper left")
plt.show()
     
For the single cloud, about 45% of the simulations produce a ratio as small as or smaller than the observed one. Its split is ordinary under this reference, despite the tiny t-test p-value.

For the overlapping clouds, none of the 499 simulations produces a ratio as small as the observed one. The table reports 0.002 because we add one to both the count and denominator: . This avoids reporting zero from a finite simulation. The observed split is unusually strong compared with splits of the fitted Gaussian samples.

This is approximate evidence against the chosen one-Gaussian description. We estimated that reference from the data, and have not checked whether a cutoff such as 0.05 would have the intended false-positive rate. A single population with a skewed or heavy-tailed shape could also depart from this reference; an unusual split alone does not establish multiple populations.

Scoring New Observations
The calculations above assess observations within one collection. For a healthy reference collection followed by new readings, scikit-learn calls the task novelty detection. The reference data and the observations being assessed have different roles.

LOF uses a separate interface for that task: set novelty=True before fitting the reference collection, then score new observations. Those novelty calls should be used for new observations; applying them to the training collection does not reproduce the fitted-collection scores used here. Isolation Forest can route new observations through its fitted trees using score_samples.

In either case, choose a reference that represents the operating conditions relevant to the investigation.

Contamination And Masking
Two additional effects can make it difficult to identify anomalies.

Reference contamination occurs when the fitted reference contains behavior we intend to detect as abnormal. Those observations can influence the pattern used to assess them. Could a concerning observation receive a low score because of that influence?

Masking occurs when abnormal observations make one another appear less unusual. The following construction keeps the accepted background and one focal observation fixed while adding more abnormal neighbors.

Generate 200 accepted observations near the origin and a tight remote group. By construction, the remote group contains the observations of interest. Compare five remote observations with thirty, always using 20 LOF neighbors. The circle identifies the same observation in both panels.

Explain The Score Change
The focal observation has not moved. Why does its LOF fall from about 6.19 to 1.01? Use the number of nearby companions and the 20-neighbor requirement to explain the difference.

Test Agreement Against Random Selection
Validation evaluates whether evidence supports the intended claim. LOF finds seven low-rated wines in 50 reviews. A uniform random selection would find about 50 × 63 / 1599 ≈ 1.97 on average. Use a one-sided hypothesis test to assess that difference.

Null hypothesis: the selected set has no greater concentration of low ratings than a uniform random selection of 50 records.
Alternative hypothesis: the selected set has a greater concentration of low ratings.
Test statistic: the number of low-rated wines among the 50 selected records; the observed value is seven.
Construct the null distribution by repeatedly selecting 50 distinct records uniformly at random from this collection. Keep the observed ratings, collection size, and review count fixed.

Novelty Detection
Novelty detection assesses new observations against an established reference representing normal behavior. We will assume that the wine collection can stand as an established reference for this section. To carry out the new-observation evaluation above with LOF, fit the chosen reference using its novelty interface.

A fitted Isolation Forest already contains split rules. If a tree first splits at 25 and then splits its right branch at 65, a new value of 30 travels right, then left. Its path contributes to the score across the fitted forest.

Scoring preserves the fitted reference; refitting changes it. The masking example refitted after adding observations. With a fixed novelty reference, newly scored observations do not become reference neighbors merely by being scored.

LOF's novelty calls should not be used to reproduce its training scores; those remain available through negative_outlier_factor_. Deciding when to accept new behavior into the reference is part of the application.

Decomposition Approach
We will represent each observation as the sum of a trend-cycle, a seasonal component, and a remainder. This is an additive decomposition: all three components are measured in GWh. For this example, we assume the seasonal pattern repeats unchanged each year.

Estimate the slower movement. Use a moving average to estimate the trend-cycle.
Look for a repeating annual pattern. Subtract the trend-cycle and compare the remaining values for the same month across years.
Estimate the seasonal component. Calculate a typical effect for each month and repeat those 12 effects across the series.
Inspect what remains. Subtract both estimated components from the observations. The remainder contains variation this decomposition has not explained.
The trend-cycle can rise and fall; it need not follow a straight line.

Estimate the Trend-Cycle With a Moving Average
Average the first 12 months, January through December 2001. Then move forward one month and average February 2001 through January 2002. Continue moving the window one month at a time. Each average includes a full year of observations and smooths the within-year swings. Compare the large annual swings in the observations with the slower movement of the average.


trend_cycle = nuclear.rolling(window=12).mean()

Classical Limitations and STL
The manual calculation made the decomposition steps visible, and classical decomposition packaged them into a library call. For practical decomposition in this course, we will use STL. It keeps the same component meanings while giving us more control over how they are estimated.

Limits of the Earlier Approach
Three limitations follow from the calculations we used:

The seasonal pattern is fixed. Every January receives the same effect, whether it is 2001 or 2024. Changes in that pattern must go into the trend-cycle or remainder instead.
Moving averages need complete windows. Our trailing average lost the first 11 months and lagged changes in level. The centered classical estimate lost six months at each end. A fixed window can also smooth over a rapid change.
Unusual observations influence the averages. A very low production month can pull down both the trend estimate and the seasonal average for its calendar month. Some of that unusual departure can be absorbed into the components we are trying to estimate.
These are reasons to use a more flexible estimator, rather than repeat the manual procedure for every new series.

STL: Local Smoothing and Robust Fitting
STL means Seasonal and Trend decomposition using Loess. Loess estimates a smooth curve by fitting simple relationships to nearby observations, giving more influence to closer observations. STL alternates between estimating seasonal and trend-cycle structure.

This changes what the decomposition can do:

Seasonal effects can evolve. A January estimate borrows information from nearby Januaries rather than assigning one average to every year.
Smoothing settings control how quickly the components can change. Local fits also provide endpoint estimates using the observations available there, although endpoints have less balanced support than interior dates.
Robust fitting reduces the influence of observations with large remainders when estimating the components. Their departures remain visible in the remainder instead of pulling the fitted curves as strongly.
We will use an additive STL decomposition on the original GWh scale, with robust fitting enabled.

Fit the Nuclear-Generation Series
Create an STL specification for the same monthly series, then call .fit() to estimate its components.


from statsmodels.tsa.seasonal import STL

stl_model = STL(nuclear, period=12, seasonal=13, robust=True)
stl = stl_model.fit()

# check that the components cover the record and reconstruct the observations
assert stl.trend.notna().all()
assert stl.seasonal.notna().all()
assert stl.resid.notna().all()
np.testing.assert_allclose(stl.trend + stl.seasonal + stl.resid, nuclear)
     
The settings have different jobs:

period=12 specifies the annual cycle: 12 monthly observations.
seasonal=13 controls smoothing across successive occurrences of the same calendar month. For monthly data, it uses a neighborhood of 13 annual occurrences, such as nearby Januaries. This deliberately favors gradual seasonal change over year-to-year fluctuations; it is an illustrative choice, not an optimized setting. The window must be odd. The statsmodels default is 7.
robust=True enables the reweighting of unusual observations. The default is False.
We leave the trend smoother at its library-selected setting. With these choices, statsmodels uses a 21-observation trend window. Unlike seasonal, that window refers to consecutive months.
The fitted result exposes .trend, .seasonal, and .resid, just as the classical result did. The meanings and units of those components have not changed.

Seasonal Adjustment
Is nuclear generation declining or recovering, and which months depart from that broader movement? The recurring annual peaks and troughs make those changes harder to see. We want to examine generation with the usual seasonal pattern removed.

Seasonal adjustment does this by subtracting the estimated seasonal component from each observation. We use the seasonal estimates from our STL fit:

The adjusted series is still measured in GWh. For a month with a positive seasonal effect, we subtract that expected boost; for a month with a negative seasonal effect, subtracting it raises the adjusted value. This puts different months on a more comparable basis.

Plot the adjusted series alongside the observations and the trend-cycle over the same 2007–2016 window. Look for the broader changes and the departures that remain after removing seasonality.

Connection to Dependence
After removing the estimated trend-cycle and seasonality, are observations in the remainder independent, or do they still have time dependencies? For example, does a positive remainder tend to be followed by another positive remainder? If so, the decomposition has left some time-related structure unexplained.

In the next lecture, we will use lags and autocorrelation to investigate that remaining dependence. An absence of autocorrelation alone does not establish independence.




11b: Autocorrelation, Stationarity, and Differencing
On Tuesday, we separated trend-cycle and seasonality from monthly nuclear generation. The remainder contained what those estimated components did not explain. We ended with a question: does a positive remainder tend to be followed by another positive remainder?

Today we will describe relationships between observations separated in time, then ask whether those relationships remain consistent through the record. We will examine both levels and changes.

The methods used herein can be applied to an original series, a seasonally adjusted series, or a decomposition remainder; always identify which one is being examined.

Autocorrelation
Correlation measures the strength and direction of a linear relationship between two variables.

 

Values near +1 indicate a strong positive linear relationship, values near −1 a strong negative linear relationship, and values near zero little linear relationship.

Autocorrelation measures the linear relationship between values in a series and its own earlier values. There is a separate coefficient for each lag. A positive value indicates that above-average observations tend to pair with above-average observations; a negative value indicates that above-average observations tend to pair with below-average observations.

For  observations with overall mean 
, the sample autocorrelation at lag  is

 

The numerator combines the centered products for available pairs. Products are positive when the two values are on the same side of the mean and negative when they are on opposite sides. The denominator puts the result on a common scale using the variation in the full series.

Calculate lag 4 manually using this sample-ACF estimator. It uses one overall mean and denominator across lags. Pearson correlation instead centers and scales each pair of shortened columns separately, so the two calculations can give slightly different results.


h = 4
# Center once using the mean of the full selected series.
centered = beer - beer.mean()
# Only complete current/lagged pairs contribute to the numerator.
products = (centered * centered.shift(h)).dropna()
numerator = products.sum()
# Use all centered observations for the common normalization.
denominator = (centered ** 2).sum()
r4 = numerator / denominator
display(pd.DataFrame({"Centered current": centered,
                      "Centered lag 4": centered.shift(h),
                      "Product": centered * centered.shift(h)}).dropna().head())
print(f"Lag 4: {numerator:.2f} / {denominator:.2f} = {r4:.3f}")
     
Multiplication aligns the two Series by their date labels. After shifting, .dropna() keeps the complete pairs for the numerator. The denominator sums squared deviations over the full series, matching the displayed formula. The resulting lag-4 coefficient is about 0.802.

The autocorrelation function, or ACF, collects the correlations across lag values. The acf function estimates them from our series. Display lags 1–9 to connect them with the nine lag plots.


# Estimate autocorrelations at lags 0 through 16.

# Display lags 1 through 9; array position zero is lag zero.

Trend and Seasonality in the ACF
A repeating seasonal pattern can produce positive correlations at multiples of its period. A changing level can also produce strong autocorrelation: observations close in time share a similar level, even when they come from different parts of a long upward trend.

Australian antidiabetic drug sales illustrate this combination. def show_series_acf(series, title, ylabel, lag_unit, lags=24):
    fig, axes = plt.subplots(1, 2, figsize=(12, 3.8), layout="constrained")
    # Left panel: values in their original time order.
    axes[0].plot(series.index, series, color=BLUE, lw=1.2)
    axes[0].set(title=title, ylabel=ylabel,
                xlabel="Date" if isinstance(series.index, pd.DatetimeIndex) else "Period")
    # Right panel: correlations across lags, with white-noise reference bounds.
    plot_acf(series, lags=lags, zero=False, bartlett_confint=False,
             ax=axes[1], auto_ylims=True)
    # Keep the correlation axis within its possible range.
    low, high = axes[1].get_ylim()
    axes[1].set_ylim(max(-1, low), min(1, high))
    axes[1].set(title="Autocorrelation", xlabel=f"Lag ({lag_unit})", ylabel="ACF")
    plt.show()
    plt.close(fig)

White Noise
What would the ACF look like without underlying time dependence? How might we use that to create a numerical test?

A white-noise process has mean zero, constant finite variance, and zero autocorrelation at every nonzero lag. Independent random draws with the same distribution provide one way to generate it. The ACF measures linear dependence. Other forms of dependence can exist even when the autocorrelations are zero.

Generate 50 independent standard-normal values and examine their time plot and ACF. The generating process has no autocorrelation; the estimated correlations in this one short sample will still fluctuate.


# Fix the seed so this illustration is reproducible.
random = np.random.RandomState(30)
# Draw 50 independent values with mean zero and standard deviation one.
white_noise = pd.Series(random.normal(0, 1, 50), index=np.arange(1, 51))
show_series_acf(white_noise, "Simulated white noise", "Value", "periods", lags=16)
     
normal(0, 1, 50) draws 50 values with mean zero and standard deviation one. The seed fixes the sample for repeatable discussion. The index labels the generated observations 1 through 50.

We can use white noise as a reference: how large might a sample autocorrelation be when the underlying autocorrelation is zero?

It can be shown that, for a sufficiently long white-noise series, the sample autocorrelation at a specified nonzero lag falls approximately 95% of the time between

 
 

Here  is the number of observations. For 50 observations, the bounds are approximately ±0.28. An estimated autocorrelation inside this band is compatible with the random variation expected around zero; one outside it gives evidence of linear dependence at that lag. A longer record gives narrower bounds.

These are pointwise bounds: the 95% statement applies to one specified lag. When we inspect many lags, chance crossings become more likely. Our simulated sample illustrates this: its first spike is just outside the band even though the observations were generated independently.

Stationarity
Autocorrelation summarizes pairs taken from different parts of the record. When is it reasonable to describe those pairs with one relationship? We need to ask whether the properties of the process stay consistent through time.

A stationary time series is one whose statistical properties do not depend on the time at which the series is observed. More precisely, if 
 is a stationary time series, then for all , the distribution of 
 does not depend on .

A changing mean, a changing spread, or a fixed calendar-seasonal pattern violates stationarity. Our independent standard-normal draws have the same distribution at every time and are stationary. A stationary process can also have dependence, provided its joint distributions remain unchanged when shifted in time.

We will compare Google’s 2015 closing prices with their changes. First, inspect the levels alongside our other examples. Each Google row is an observed trading day. Lag 1 means the previous trading observation; a weekend or exchange holiday can separate consecutive observations by several calendar days.

A Joint Check for Autocorrelation
The Ljung–Box test checks autocorrelations jointly over a selected range of lags. Its null hypothesis here is that the population autocorrelations at lags 1 through 10 are all zero. A small p-value provides evidence against that hypothesis. A large p-value means the observed autocorrelations are compatible with that hypothesis.

Apply the test to the price changes over the first ten lags.


# Jointly test zero autocorrelation at lags 1 through 10.
ljung_box = acorr_ljungbox(google_change, lags=[10], return_df=True)
display(ljung_box.round(3))
     
lags=[10] requests one joint test covering lags 1–10. The output row is labeled by that maximum lag. lb_stat is the test statistic and lb_pvalue is its p-value; the following interpretation uses the p-value.

The p-value is about 0.637. The autocorrelations across the first ten lags are compatible with the white-noise reference, agreeing with the relatively quiet ACF.

Random Walks
How can a series have a wandering level while its changes have no autocorrelation? Consider a process that starts at a fixed value and adds a new, independent, zero-mean random change at each step:


This is a random walk. Here 
 is the new random change. Rearranging gives


The levels accumulate the changes; differencing recovers them. A run of positive or negative changes can produce apparent trends without a persistent upward or downward force.

Simulate 200 independent changes and accumulate them, starting at zero. Compare the wandering path with the changes that generated it.


rng = np.random.default_rng(7130)
# Generate independent changes, then accumulate them into levels.
steps = rng.normal(0, 1, 200)
# Prepend the fixed starting level so all 200 changes can be recovered.
walk = pd.Series(np.r_[0.0, np.cumsum(steps)])
walk_change = walk.diff().dropna()
# Check that differencing recovers the changes used to construct the walk.
np.testing.assert_allclose(walk_change, steps)
show_series_acf(walk, "Simulated random walk", "Level", "periods")
show_series_acf(walk_change, "Random-walk changes", "Change", "periods")
     
np.cumsum(steps) accumulates the random changes. np.r_[0.0, ...] places the starting level before those accumulated values, giving 201 levels for 200 changes. Applying .diff() recovers the increments, which the assertion verifies.

The changes were generated independently, but neighboring levels share most of the same accumulated history. That creates strong dependence in the levels.

This random walk is not stationary: after more steps, more independent changes have accumulated, increasing the uncertainty about its level. With step variance one and a fixed starting value, the variance of the level after  steps is . A constant expected level alone is not sufficient for stationarity.

If future changes have expected value zero, the current level is the expected future level. That gives a simple prediction: use the latest observed value. The next observation will also include a new random change.

The quiet ACF of Google’s price changes illustrates why this simple prediction is worth evaluating.

Seasonal Differencing
For a seasonal series, consecutive observations can belong to very different parts of the cycle. We can instead compare corresponding positions in successive cycles. With  observations per cycle, the seasonal difference is


For monthly observations with an annual pattern, . The result measures the change since the same month last year. We lose the first 12 observations, which have no year-earlier counterpart in the record.

This differs from Tuesday's seasonal adjustment. Seasonal adjustment subtracts an estimated seasonal component and retains the level. Seasonal differencing subtracts an earlier observation and produces a change.

If the same-month change had expected value zero and no useful predictable structure, the corresponding simple prediction would be last year's value for that month. We will evaluate predictions such as these against later observations in the forecasting lecture.

Choosing the Difference
The subtraction should match an interpretable question: change since the previous period, or change since the previous corresponding season. Afterward, inspect both the time plot and the ACF. Unnecessary differencing can introduce dependence and make the series harder to model.

Optional note: A second ordinary difference is a change in consecutive first differences. It is not a lag-2 difference. A seasonal difference can also be followed by an ordinary difference when justified; that is a different operation from two ordinary differences.

What the Evidence Supports
We began with the question left by decomposition: is there still a relationship between observations separated in time?

Lag plots make the pairs visible; autocorrelation summarizes their linear relationships.
White noise supplies a reference for the sample variation we can see even without underlying autocorrelation.
Stationarity asks whether statistical behavior remains consistent when we shift our observation window through time.
Ordinary and seasonal differences change the quantity under study, which can make its behavior more consistent.
The next question is whether any remaining structure helps us predict observations that were not available when we made the prediction. That requires a forecast and an honest comparison with what happened afterward.

Training and Test Series
We can use the results from seasonal decomposition to predict future observations. To demonstrate, we'll use the following function to split the time series into a training series, which we'll use to generate predictions, and a test series, which we'll use to see whether they are accurate.


def split_series(series, n=60):
    training = series.iloc[:-n]
    test = series.iloc[-n:]
    return training, test
     
With n=60, the duration of the test series is five years, starting in July 2019.


training, test = split_series(nuclear)

# show the timestamp for the first observation of the test set
test.index[0]
     
Our objective is to use the training data to build a predictive model and use the test data to evaluate its performance. This is the classic supervised learning pattern.

Our training data ends June 2019, and test data begins the following month. We want to forecast (predict) the value of observations for July 2019 on, for the same dates as the test data.

Every model and decomposition below will be fit using training only.

A Linear Regression Baseline
Use linear regression to fit a straight line to the observed training series using scikit-learn.

This baseline uses elapsed time as its only predictor. For now, we will ignore seasonal predictors and other patterns that we know contribute.

Count months from the beginning of the series. Fit the relationship between month number and observed generation, then extend the same time coordinate into the test period.

LinearRegression is scikit-learn’s ordinary least-squares regression estimator. LinearRegression() creates the model; fit(X, y) estimates the coefficients that minimize squared differences between observed and fitted values. Here X is a table with one predictor column, month number, and y is observed generation. After fitting, predict(X) returns predictions for the supplied month numbers.


months = np.arange(len(nuclear))
X = pd.DataFrame({"months": months}, index=nuclear.index)
X_train = X.loc[training.index]
X_test = X.loc[test.index]

baseline = LinearRegression()
baseline.fit(X_train, training)
baseline_pred = pd.Series(baseline.predict(X), index=nuclear.index)
baseline_forecast = baseline_pred.loc[test.index]

display(pd.Series({"Intercept (GWh)": baseline.intercept_,
                   "Slope (GWh per month)": baseline.coef_[0]}).round(2))
     
fit estimates the intercept and slope from the training observations. predict applies those fitted coefficients to the supplied month numbers. The test months continue the original count as the only predictor.


training.plot(label="training", **actual_options)
baseline_pred.plot(label="linear regression", **model_options)
plt.axvline(test.index[0], color="0.4", ls=":", label="test period begins")

This result is a simple estimate of a linear trend. It captures the overall direction and rate of change across the training period, but it does not isolate that trend. Seasonal variation, longer cycles, and unusual observations can influence the fitted line.

The straight line cannot reproduce the annual peaks and troughs. Can a forecast that retains the seasonal pattern do better?

A baseline is a simple reference model against which we compare other approaches. This straight-line forecast establishes what we can achieve using only elapsed time. A more elaborate method should earn its additional complexity through a useful improvement on the same prediction task. We will compare both forecasts against the same withheld observations.

Prediction With Decomposed Components
Now, suppose it's June 2019 and you are asked to generate a five-year forecast for electricity production from nuclear generators. To answer this question, we'll use the training data to make a model and then use the model to generate predictions. We'll start with a seasonal decomposition of the training data.

In 11a, we used statsmodels’ seasonal_decompose to estimate the trend-cycle, seasonal component, and remainder. The opening figure recalls our previous decomposition using STL. Here we return to the classical additive decomposition also used in 11a, with period=12 for the annual cycle.

This time we pass only training, so the withheld observations cannot influence the estimated components.


decomposition = seasonal_decompose(training, model="additive", period=12)
trend = decomposition.trend
     
Now we'll fit a linear model to the estimated trend-cycle. The explanatory variable, months, is the number of months from the beginning of the series.

The library calls this component .trend, and we keep trend as the variable name. Classical decomposition estimates trend and longer, nonseasonal cycles together. The regression fits a straight line through that combined estimate so we can extrapolate it.


months = np.arange(len(trend))
data = pd.DataFrame({"trend": trend, "months": months}).dropna()
trend_model = LinearRegression()
trend_model.fit(data[["months"]], data["trend"])
     
Here is a summary of the results.


display(pd.Series({

}))
     
The  value is about 0.35, which suggests that the straight line does not fit the estimated training trend-cycle particularly well. We can get a better sense of that by plotting the fitted line. We'll use the predict method to compute expected values for the training and test data.

Next we'll use the seasonal component from the decomposition to compute a Series of monthly averages.

To quantify the accuracy of the predictions, we'll use the mean absolute percentage error (MAPE), which the following function computes.


def MAPE(predicted, actual):
    ape = np.abs(predicted - actual) / actual
    return np.mean(ape) * 100

A Packaged STL Forecast
Let's compare our explicit component forecast with another procedure using STLForecast. It estimates seasonality with STL, forecasts the seasonally adjusted series using a model we supply, and adds the seasonal forecast back automatically.

We supply ARIMA for the adjusted series, with the illustrative settings used in the statsmodels example. Consider this a preview: we will return to the model and explain its settings in the ARIMA lecture. These settings have not been selected by trying alternatives on our test observations.


stl_forecaster = STLForecast(
    training,
    ARIMA,
    model_kwargs={"order": (1, 1, 0), "trend": "t"},
    period=12,
    seasonal=13,
    robust=True,
)
stl_result = stl_forecaster.fit()
stl_forecast = stl_result.forecast(steps=len(test))
assert stl_forecast.index.equals(test.index)
assert stl_forecast.notna().all()

stl_forecast.plot(label="STL + ARIMA forecast", color="C4", lw=1.8)
test.plot(label="actual", **actual_options)
finish_plot("Packaged forecast versus withheld observations")
     
The constructor specifies the decomposition and forecasting model, fit() estimates them from the training history, and forecast() returns predictions for the next 60 months. Here seasonal=13 retains the seasonal smoother used in our earlier STL example; period=12 specifies the annual cycle.

STL estimates the components; ARIMA supplies the rule for forecasting the adjusted series. STLForecast repeats the last estimated seasonal cycle and adds it to that forecast. This is an alternative forecasting procedure, not an equivalent packaged version of the preceding calculation: both decomposition and extrapolation change, so an accuracy difference cannot be attributed to STL alone.

Accuracy Across the Forecast Period
The previous table averages errors across all five years. Let's see how accuracy changes over the forecast period. We will use the same predictions and calculate MAE and RMSE separately for the first year, the second year, and the remaining three years.

Leakage
Be very careful to preserve the boundary between train and test data. Training a model on observations from dates you later plan to predict is a form of leakage because it leaks information about the future into the predictive model.

This form of leakage is rather obvious. Others are more subtle, covert, or even slightly sinister!

Leakage can also occur in project preprocessing, feature selection, or model settings if those stages use outcomes reserved for evaluation.

Preprocessing before splitting. Estimate missing-value replacements, scaling parameters, or PCA directions using the full dataset, then evaluate on its held-out portion. The test observations have already influenced the representation.
Features that look ahead. Calculate a centered rolling average or fill a gap using later observations, then use that value in a forecast supposedly made earlier.
Information recorded after the decision. Use a final inspection result or a repair code to predict whether equipment will need attention before the inspection occurs. The field is present in the completed dataset but would not have been available at prediction time.
Overlapping observations across the split. Put nearly identical sensor windows in training and test sets, then claim performance on new operating episodes. Much of the same signal appears on both sides. Choose the split to match the intended use; evaluating on new entities may also require keeping each entity’s records together.
Outcomes hidden in the inputs. Include a service-escalation label, or a field that effectively encodes it, when clustering customer records, then use separation by escalation status as independent evidence that the clusters are meaningful. That comparison is circular because the outcome helped form the groups.
Describing a complete dataset is legitimate. The problem is using that description as evidence of prediction or independent validation when the information used to build the result already contains what we later claim to evaluate.

Fit data-dependent operations inside the available training history. If we repeatedly change these forecasts after inspecting this test period, we are using it for model development and need a separate final evaluation.

What would change if we forecast one year instead of five, or started at a different date? Repeating the comparison at successive forecast origins will let us investigate that next time.
