Homework 3a: Clustering, Purpose, and Evidence
One of the main arguments in Clustering: Science or Art? is that there is no universal way to decide whether a clustering result is good or bad. Instead, the quality of a clustering depends on why the data are being clustered in the first place. I agree with this argument because clustering is often used to support a larger goal, and different goals can require very different groupings of the same data.
This idea ties in with a theme that has come up repeatedly in this course. Finding a pattern in data does not automatically mean we have learned something useful. Whether we are looking at neighbors, visualizations, or clusters, we still have to ask what the results represent and whether they help answer a meaningful question. The paper argues that many clustering researchers focus too heavily on algorithm performance while ignoring the actual reason someone wants to cluster the data. I think that criticism is fair. It is easy to get caught up in metrics and forget that the end goal is to support decision-making or generate knowledge.
I also found the discussion about benchmark datasets convincing. The authors point out that researchers often compare clustering results with existing class labels and assume that better agreement means better clustering. However, a dataset can contain multiple meaningful structures at the same time. Their example of clustering images by color instead of object type shows that a clustering can be reasonable even when it does not match the labels. That stood out to me because it highlights how much our expectations influence what we consider a "good" result.
That said, I think the paper may go a little too far in downplaying general evaluation measures. I agree that metrics such as cohesion, separation, or stability cannot tell us whether a clustering is useful for every possible application. However, they can still provide valuable evidence. If a clustering changes dramatically whenever the data are slightly modified, I would be hesitant to trust it, especially in a research setting. Even if these metrics cannot tell us the whole story, they can help identify results that may not be reliable enough to support conclusions.
My experience in engineering research also makes me lean toward the authors' perspective. In many cases, the most useful analysis is not the one with the best mathematical score but the one that helps explain a real-world problem. For example, when analyzing biological or environmental data, a grouping that helps explain a process or suggests a new hypothesis can be more valuable than one that simply optimizes an objective function.
Overall, I agree with the authors that clustering should be evaluated in the context of its intended use rather than against a universal standard. At the same time, I think general quality measures still have an important role as supporting evidence. Just like with many things in life, the strongest approach is probably to incorporate both ideologies: evaluate whether the clustering is technically sound while also asking whether it actually helps answer the question that motivated the analysis in the first place.

The functions below summarize and display results. show_groups(labels, title) takes a set of cluster labels and a title, prints customer counts and category medians, then plots Fresh against Grocery spending on logarithmic axes. def spending_profile(labels):
    """Return customer counts and median spending for each assigned group.

    Supply one label per customer, in the same row order as `customers`.
    The table uses the six original spending columns in monetary units,
    not the transformed values in `X`. DBSCAN label -1 appears as "Noise".
    """
    grouped = customers.assign(group=labels).groupby("group")
    table = grouped[FEATURES].median()
    table.insert(0, "Customers", grouped.size())
    return table.rename(index={-1: "Noise"})


def show_groups(labels, title):
    """Display a spending summary and a Fresh-versus-Grocery plot.

    Supply one label per customer in row order and a title for the display.
    The table shows group sizes and median spending in all six categories.
    The plot shows only Fresh and Grocery on logarithmic axes, so it cannot
    show every difference used in clustering. Gray crosses mark DBSCAN noise.
    """
    if labels is None:
        print("No labels exist.", title)
        return
    print(title, ": category medians in original monetary units")
    display(spending_profile(labels).round(1))
    fig, ax = plt.subplots(figsize=(7, 4.5), layout="constrained")
    palette = plt.get_cmap("tab10")
    for group in np.unique(labels):
        rows = customers.loc[labels == group]
        ax.scatter(
            rows["Fresh"], rows["Grocery"], s=18, alpha=0.65,
            color="0.55" if group == -1 else palette(int(group)),
            marker="x" if group == -1 else "o",
            label="Noise" if group == -1 else f"Group {group}",
        )
    ax.set(
        xscale="log", yscale="log", xlim=(2, 150_000), ylim=(2, 150_000),
        xlabel="Fresh spending (m.u.; log axis)",
        ylabel="Grocery spending (m.u.; log axis)", title=title,
    )
    ax.legend(fontsize=8)
    plt.show()


def density_summary(labels):
    """Return the number of DBSCAN groups, assigned customers, and noise customers.

    Supply the fitted DBSCAN labels, one per customer. Label -1 means noise
    and is excluded from the group count. The two customer counts describe
    how many records received a group assignment and how many did not.
    """
    return {
        "Groups (excluding noise)": len(set(labels) - {-1}),
        "Customers in groups": int(np.sum(labels != -1)),
        "Noise customers": int(np.sum(labels == -1)),
    }

1b. Interpret the LOF Score

The LOF score for observation 0 is 0.900, which indicates that its local reachability density is slightly higher than the average density of its two nearest neighbors. In other words, observation 0 has relatively strong local support compared to its neighbors and is not particularly isolated.

The LOF score does not represent the probability that an observation is faulty. Instead, it is a relative measure of local density. A score near 1 indicates similar density to neighboring observations, while a score substantially greater than 1 suggests that an observation is less densely surrounded and may be a local outlier. Therefore, an LOF score alone cannot determine whether an observation is faulty.

def score_forecasts(actual, predictions):
    """Return metrics and actual-minus-predicted errors for matching date indexes.

    actual is a Series; predictions is a DataFrame with one column per method.
    This checks alignment, not whether model fitting used permissible information.
    """
    if not actual.index.equals(predictions.index):
        raise ValueError("Actuals and predictions must have the same dates in the same order.")
    if actual.isna().any() or predictions.isna().any().any():
        raise ValueError("Every evaluated date needs an actual and each method's prediction.")
    errors = predictions.rsub(actual, axis="index")
    scores = pd.DataFrame({"MAE": errors.abs().mean(),
                           "RMSE": np.sqrt(errors.pow(2).mean()),
                           "Mean error": errors.mean()})
    return scores, errors
